Step 5 · Install the integration

Curated Thoughts Integrations is a collection of ready-made connectors — one per agent harness. This step installs the Hermes one, which upgrades your wiring from step 4 into something smarter.

Each integration ships the same layers, adapted to its harness: registration (so you don't hand-edit config), a doctor that checks the whole setup and explains anything broken, agent skills that teach it how to use the memory correctly, and Intuitive Wisdom — remembered facts that arrive in the agent's context when they're relevant, without the agent having to remember to ask.

  1. Download and unpack the release. A release is a packaged snapshot of the plugin, ready to download. Go to the releases page for the Hermes integration and pick the newest release whose tag starts with hermes-v — download its hermes-<version>.tar.gz asset. The version number will be higher than the examples here by the time you read this; that is fine, the newest hermes-v… release is always the right pick. Don't grab the deepseek-v… or opencode-v… releases sitting next to it — those are for other harnesses. A .tar.gz file (a tarball) is a zipped folder; unpack it in a terminal:
    tar xzf hermes-0.7.2.tar.gz
    (0.7.2 is an example — use the name of the file you downloaded.) You now have a hermes-0.7.2/ folder; your version number replaces 0.7.2 in every command below.
  2. Run the installer. A plugin is an add-on that Hermes loads; the installer copies everything into place under ~/.hermes/plugins/curated-thoughts/. It is safe to run again any time and needs no administrator rights:
    bash hermes-0.7.2/scripts/install.sh
    What you should see: near the end, under == Plugin enablement ==, either an OK: line or a block to paste; the run finishes with == Done ==. The installer never overwrites an entry you already have. Without the plugins entry the tools work but the integration's skills and session-start recall stay switched off (step 3 below shows where that block goes).
  3. Place the printed config blocks. The installer may print a config block, with a message saying where it goes. Follow that message — and match it to what your file shows:
    • If it prints an mcp_servers block and says “No mcp_servers: section found. Add the following to ~/.hermes/config.yaml” — paste the whole block at the top level of the file, exactly as printed, keeping its indentation. You usually see this if you skipped the hand-edit from tutorial step 4.
    • If it says “An mcp_servers: section exists but has no curated-thoughts key. Insert the following block INSIDE that section (indent one level)” — don't paste the block whole: the printed copy still carries its own mcp_servers: header line, and nesting that inside your existing section breaks the config. Copy every printed line except that header, shifted left so curated-thoughts: sits one indent level under your existing mcp_servers: (the command: line may differ if you have set HERMES_CT_SIDECAR). Without any live env: lines, the result looks like:
      mcp_servers:
  curated-thoughts:
    command: curated-thoughts-mcp
    args: ["--mcp"]
      If the printed block includes live env: lines — the installer prints them when it detects a setting the sidecar needs forwarded, like a brain outside its default location or an external embedder — keep all of them; the snippet above leaves them out. Lines starting with # are just a fallback hint: keep or delete them — if you use an external embedder, uncomment the OPENROUTER_API_KEY pair (renaming both occurrences on that line to OPENAI_API_KEY or EMBED_API_KEY if that is the one you use, and only if that variable is set), but only when the block has no live env: lines — otherwise you would end up with a second env: key. And keep whatever entries are already in your section.
    • If it prints a plugins block — that is what switches the integration on — and says “No plugins: section found”, paste the whole block at the top level. If it says a plugins: section “exists but does not list curated-thoughts”, add just the one line under enabled: inside that section (create enabled: if it isn't there), keeping whatever else is already listed:
      plugins:
  enabled:
    - curated-thoughts

Privacy and model choices are in step 3; checking that memory works is step 6.

Other harnesses welcome: the same repo ships integrations for Claude Code, OpenCode, DeepSeek Harness, OpenClaw, and Docker Agent. Your company's memory can feed every agent you use — see the link directory.
