Step 6 · Check that memory works

The integration is installed — but installed isn't working. This page checks each layer, in a few minutes, and tells you exactly what to fix if something's off.

  1. Run the doctor. The integration ships a doctor — a script that checks each layer of the setup and explains anything broken:
    python3 ~/.hermes/plugins/curated-thoughts/scripts/ct_doctor.py check
    What you should see: one line per check — the sidecar (the helper program that serves your memory), the brain (its live database), the vault (your files of durable facts), the registration (the config entry that lets Hermes find the sidecar), plus a few more checks (import pre-flight, version compatibility) — most lines saying PASS, then a tally like 0 FAIL, 1 WARN, 9 PASS. 0 FAIL is the goal. WARN means that layer works but a feature is degraded — the line's fix: hint says exactly what to do. FAIL means stop, do what the line says, and run the doctor again. The aside below decodes WARN lines and exit codes.
  2. Restart Hermes and look for the session-start recall. Quit and reopen Hermes, then start a fresh session: you should get a short recall of relevant procedures and facts. On each message, the integration's Intuitive Wisdom may add a remembered fact on its own — when a message touches something your memory knows. Corrections you approve always flow. If nothing shows up at all: re-run the doctor, make sure plugins.enabled lists curated-thoughts, and make sure Curated Thoughts itself is version 3.3.0 or newer — older versions can't deliver live facts.
  3. Ask something only your vault knows. Pick a fact you know is in the files you added in step 2 and ask your agent: "search my vault for what I said about X". If it comes back with your fact, the whole pipe — vault to brain to sidecar to agent — works, apart from automatic delivery.
  4. Know what's happening under the hood, and turn on verbose mode to see it. When a message touches something your memory knows, the fact arrives on its own — without you asking. Verbose mode shows every decision: run Hermes with CT_WISDOM_VERBOSE=1 set, then read the log:
    python3 ~/.hermes/plugins/curated-thoughts/scripts/ct_wisdom_log.py --host hermes -n 5
    The log lives at ~/.hermes/logs/ct-wisdom-verbose.jsonl. The reasons, in plain words: no_match (nothing in memory matched the message), deduped (a match was found but had already been shown), gate_uncalibrated (your embedder isn't covered by your Curated Thoughts version's calibration yet — updating extends coverage).

Reading the WARN lines and exit codes: a common WARN is the embedding-backend hint — on the default local setup you don't have to set up any embedding model; with no embedding API key and no Ollama running, semantic search falls back to the sidecar's built-in local model (slower; downloads on first use), and plain text search of your vault works regardless. If the installer's mcp_servers section said OK but printed env names under it, make sure your existing entry carries those names — the sidecar-env check reports any that are missing. The doctor exits with 0 when everything passes, 1 when something failed, and 2 when it couldn't run at all.
