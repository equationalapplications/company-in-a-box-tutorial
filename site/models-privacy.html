Step 3 · Choose models and privacy

You can keep every default and go straight to step 4. Nothing here is required. With no setup at all, search still works: plain text search always works, and semantic search uses a small built-in model that runs inside the app.

Two settings decide how much of the clever stuff turns on: which privacy mode the app runs in, and which models do the two kinds of thinking — search (embeddings) and summary writing (generation).

  1. Check your privacy mode. Open the app's Settings → Privacy and see which card is selected. The three cards, in plain words:
    Strict (default) — nothing is sent to a cloud service for generation, and the cloud bridge stays off.
    Ephemeral cloud inference — summary pages may be written by a cloud AI, but nothing is stored there.
    Connected agent (Cloud Bridge) — Ephemeral, plus a read-only cloud connection.
    One line of scope: the modes govern generation and the cloud connection only. Embeddings (next step) follow their own setting, which by default stays on your machine — and if you point embeddings at a cloud API, the text being embedded goes to it in any mode.
  2. Choose how search understands meaning. An embedding turns text into numbers so search can find meaning, not just matching words. Three options:
    Do nothing. The app uses its built-in local model: slower, and it downloads on first use.
    Local Ollama, fully offline. Install Ollama — the setup wizard's "Set up local search" screen configures local search, and the sidecar finds Ollama at http://127.0.0.1:11434. Advanced users set embed_profile in the brain's config.json instead (the README's BYOI section shows the schema).
    Cloud API. Set embed_profile in the brain's config.json — same section. There is no Settings screen for embeddings; this is the one setting done in a file.
    If you change it later, the app re-embeds automatically (ct ingest --yes forces it). Until the embedder is calibrated, the automatic facts from step 6 stay off — step 6 explains.
  3. Choose who writes summary pages. Open Settings → Models, under AI Generation. In Strict, pick Auto-Install: a small model is downloaded to your machine and generation stays local. To use your own endpoint — local Ollama (http://localhost:11434/v1) or a cloud OpenAI-compatible API — switch to Ephemeral first (Strict keeps the form disabled), then fill in External base URL, API key (optional) and Model name, and Save.
  4. If you picked a cloud embedding key, make it reach the sidecar. Hermes launches the sidecar with a few environment variables, plus the env: lines in its config entry (step 5's installer writes them). Put the key in ~/.hermes/.env as OPENROUTER_API_KEY=<your key>; the sidecar looks up EMBED_API_KEY, then OPENROUTER_API_KEY, then OPENAI_API_KEY. Plainly: a generation API key entered in Settings stays inside the app and needs none of this.

Private by default, your choice when you want more. Strict privacy mode is on out of the box: your notes and facts never leave your machine, and cloud features stay off. No model setup is required — without an embedding key or Ollama, semantic search falls back to a small built-in local model (slower; downloads on first use) and plain text search always works. Want more? Configure embeddings by running Ollama (the wizard's "Set up local search" screen) or by setting embed_profile in the brain's config.json, and generation in Settings → Models — Auto-Install for local, or an external endpoint after switching to Ephemeral. Nothing leaves your machine until you choose a mode that allows it.
